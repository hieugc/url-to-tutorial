# UTV-007 · SQLite, tiến độ, hủy và khôi phục job

**Cam kết của backlog.** Progress, cancel, retry/resume không lặp tác động.

**Trạng thái do repo ghi tại thời điểm đóng gói.** SQLite recovery + running cancellation + persistent idempotency; SIGKILL/restart and bounded metadata/artifact retention regression PASS locally; full main CI and M3 acceptance tracked in VALIDATION.md. Merlin cập nhật bằng chứng theo bản code thực chạy.

## Kiến trúc và phạm vi thi công

StudioJobStore là class thực trong src/job-store.mjs; instance sở hữu DatabaseSync, prepared statements và vòng đời kết nối. createStudioServer sở hữu jobs:Map và promise queue chạy tuần tự. SQLite giữ snapshot JSON, filesystem giữ artifact theo UUID. Cần kiểm lại tiến độ trong lúc render, quyết định retry và phục hồi sau kill trên máy đích. Phương thức cloud của class cũng được liệt kê trong catalog, hợp đồng nghiệp vụ của chúng thuộc UTV-009.

## Ca triển khai mẫu

Hai POST cùng key và plan giống nhau, dù object keys đảo thứ tự → đúng một UUID và một lần work. Kill process sau running, khởi động lại với cùng outputRoot → row đó thành interrupted; gửi lại cùng key vẫn thấy job cũ trong cửa sổ retention. Lệnh Retry chỉ tạo lượt mới cho job read-only đủ điều kiện. Đề xuất khi dọn orphan: chỉ xét UUID dir do Studio quản lý, bảo vệ job đang chạy và xử lý lần khởi động kế tiếp nếu xóa file lỗi.

## Mã giả thi công · Khôi phục và tách retry khỏi resume

Các tên thao tác mô tả bên dưới có thể triển khai ngay trong hàm sở hữu luồng.

```text
onStart():
    jobs = store.recover()                  // queued/running cũ → interrupted
    pruneHistory()
onRetry(id,key):
    source = findJob(id,scope)
    require source exists && isSafeRetryable(source)
    return start(source.type, readOnlyWork, source.request, key, principal)
onDuplicate(key,hash):
    if existing.requestHash != hash: return 409
    return originalJobId                    // kể cả trạng thái interrupted
```
