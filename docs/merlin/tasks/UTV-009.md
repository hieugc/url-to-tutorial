# UTV-009 · Cloud API, worker cách ly và vận hành

**Cam kết của backlog.** Auth, isolation, SSRF/egress policy, quota, storage lifecycle.

**Trạng thái do repo ghi tại thời điểm đóng gói.** Browser egress-proxy hook and threat model; Cloud API/auth/tenant quotas/isolated worker are still NOT deployed; independent SSRF/security and infrastructure acceptance required. Merlin cập nhật bằng chứng theo bản code thực chạy.

## Kiến trúc và phạm vi thi công

Ranh giới triển khai gồm TLS ingress → Node control plane → store và hàng đợi → Docker adapter → worker dùng mạng riêng → egress proxy. Token admin và rollout thuộc tiến trình quản trị riêng. Snapshot đã có adapter AWS, PostgreSQL coordination, S3 audit, mTLS và break-glass. Hãy tích hợp các adapter qua factory sẵn có. SQLite job/quota vẫn là dữ liệu theo instance; với deployment nhiều API replica cần quyết định nơi thực thi quota/idempotency dùng chung trước khi nhận lưu lượng đa replica.

## Giao diện và quy cách trình bày

Task là API và vận hành, giao diện bàn giao là HTTP JSON cùng lệnh kiểm thử. Giữ Studio local-only; không thiết kế trang web nhập token riêng, font/màu không áp dụng cho JSON. Công cụ nội bộ hiển thị status chỉ dùng metadata đã lọc.

## Ca triển khai mẫu

Luồng tích hợp mẫu: token A của tenant A/project P gửi discover HTTPS → server kiểm scope/quota → reserve + enqueue → worker ghi /job → host đo usage → commit usage/audit rồi save job terminal → client GET detail và screenshot. Token B ngoài scope nhận 404 khi đọc id của A. Sau hard restart, recover trước listen; nếu job đã có usage, bỏ qua ghi lần hai. Với rollout ba replica và một replica lỗi tạm, lưu partial, resume chỉ những replica chưa được xác nhận hoặc mất khớp snapshot. Không tự chuyển bản triển khai public khi test mock xanh.

## Mã giả thi công · Khởi động tiến trình điều phối ở staging

Các tên thao tác mô tả bên dưới có thể triển khai ngay trong hàm sở hữu luồng.

```text
worker = createDockerWorkerAdapter(deployment.worker)
secretManager = createAwsSecretsManagerAdapter(deployment.secrets)
studio = await createCloudStudioFromSecretManager({secretManager, operatorAuthenticator,
    serverOptions:{...explicitServerOptions, cloudWorker:worker, cloudAuditArchive:sink.archiveBatch}})
scheduler = createAuditArchiveScheduler({archiveBatch:studio.archiveAuditBatch, ...scheduleOptions})
listenBehindVerifiedIngress(studio.server)
scheduler.start()
onShutdown(): await scheduler.stop(); closeServerAndDrainJobs()
```

## Tích hợp staging và dữ liệu cần chuẩn bị

| Phần việc | Thành phần / config cần nối | Phép kiểm để chuyển sang phần kế |
|---|---|---|
| Ingress và identity | Host cấp cloudAllowedHosts, cloudTrustedProxy và worker adapter. Reverse proxy thực hiện TLS và kiểm soát headers. Authenticator thật trả actorId và trạng thái MFA sau xác thực của nhà cung cấp. | /api/health đúng scope; request ngoài ACL bị từ chối; job/schema/usage chỉ trả dữ liệu đúng tenant. Lưu cấu hình và evidence đã lược credential. |
| Job và ngân sách | Dùng một owner cho SQLite job/quota trong giai đoạn staging đầu. Nếu cần nhiều replica nhận submit cho cùng tenant, chọn routing cố định có failover kiểm soát hoặc store giao dịch dùng chung cho key/quota; kiểm restore dữ liệu trước mở traffic. | Hai request cùng scope và key chỉ giữ một reservation; sau crash chốt usage đúng một lần; job ngoài scope không thể tải artifact. |
| PostgreSQL coordination | Cấu hình pool phía host, schema theo bốn migration bên dưới. Lease có fencing token, transaction ghi ACK/failure đúng rollout; dùng adapter thật cho kiểm thử cạnh tranh. | Thử mất lease, resume partial và điều phối hai worker; ghi rolloutId và phiên bản đã commit. |
| Secret, cert, vận hành khẩn | Dùng AWS SDK v3 cho Secrets Manager khi chọn AWS; keyProvider cấp CSR/keyRef, CA cấp/verify/revoke, replicaDirectory cài bundle. Wire certificateStore, publishLock, auditRecorder vào lifecycle. | Với cert rotate thất bại, replica giữ cert cũ hợp lệ. Với break-glass, proposer khác approver; một execution claim và audit record terminal. |
| Archive và disk | Cấu hình S3 sink có bucket/prefix/replicaId/kmsKeyId/retentionDays, schedule interval và giới hạn batch. Bảo vệ dữ liệu artifact lưu trên host và xác định tuổi lưu bằng chính sách triển khai. | Ngắt giữa upload batch và checkpoint rồi resume, đối soát hash, kiểm restore độc lập; thử disk pressure và xác nhận lỗi có thể theo dõi. |
| Release | Lưu riêng evidence Docker network recovery, firewall, certificate rotation, quota, restore và review. Host staging sở hữu cấu hình và binary. | Để OPEN cho đến khi nhà vận hành xác nhận các gate còn lại trong [hồ sơ cloud](../../CLOUD-SECURITY.md). |
