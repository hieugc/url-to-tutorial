# UTV-010 · Discovery nhiều trang và bằng chứng DOM

**Cam kết của backlog.** Status HTTP, screenshot, plan riêng mỗi trang, giới hạn và an toàn điều hướng.

**Trạng thái do repo ghi tại thời điểm đóng gói.** Same-origin navigation guard + external redirect block + public example.com smoke added; new CI candidate pending. Merlin cập nhật bằng chứng theo bản code thực chạy.

## Kiến trúc và phạm vi thi công

Explorer chạy độc lập với renderer. CLI discover/run, Studio discover và goal planner gọi explore; discover() là wrapper trả về một Plan cho caller cũ. Cần xử lý nhất quán entry URL, hàng đợi và navigation đi từ script; giữ lỗi redirect đúng trang. Khám phá read-only không đảm bảo mọi GET của site đều vô tác dụng.

## Hợp đồng hàm và thứ tự gọi

| Điểm gọi / hàm | Input và điều kiện gọi | Process cần giữ hoặc thi công | Output / lỗi |
|---|---|---|---|
| safePageLink(href,baseUrl,origin) | mỗi anchor và mỗi URL sắp khám phá | resolve URL, so origin, bỏ fragment, loại userinfo/query/asset/path tác vụ; blockedActionPath kiểm path đã decode có giới hạn | URL canonical hoặc null |
| snapshotPage(page) | sau ready và assertSafeCapture | lọc DOM visible, lấy text/aria/placeholder/title, ưu tiên heading và main, tối đa 12 ứng viên + 100 link có nhãn; ưu tiên CSS id duy nhất | snapshot chỉ chứa metadata phục vụ discovery |
| pagePlan(snapshot,language) | khi có ít nhất 1 candidate | lấy tối đa 8, title/text theo ngôn ngữ và css có trong snapshot, action highlight, holdMs 3000 | Plan overview chuẩn hóa |
| explore(url,{headed,language,maxPages,outDir,signal}) | CLI/Studio hoặc planner; maxPages nguyên 1–5 | duyệt FIFO, Set visited, tối đa 30 link/trang và hàng đợi 50; block service workers, WebSocket và HTTP ngoài GET/HEAD; main navigation từ chối redirect trước khi follow | {plan:plans[0],plans,report}; trang đầu lỗi làm job fail, trang sau có entry.error |
| discover(url,options) | caller cần đúng một manifest | await explore và lấy thuộc tính plan | Promise<Plan> |

## Ca triển khai mẫu

Điểm sửa trong explore: trước queue, phân loại entry bằng cùng policy path/query với link tự duyệt; thống nhất xử lý fragment bằng URL canonical. Trong handler main-document áp cùng policy trước route.fetch({maxRedirects:0}). Chuyển cờ refusedRedirect thành trạng thái của lần goto hiện tại, reset ngay trước mỗi lượt. Fixture 3 trang: A liên kết B và C; B redirect, C trả 404. Báo B là redirect, C là HTTP 404; A vẫn tạo được Plan. Với URL entry bị policy loại, dừng trước launch.

## Mã giả thi công · Quản lý kết quả riêng từng lần điều hướng

Các tên thao tác mô tả bên dưới có thể triển khai ngay trong hàm sở hữu luồng.

```text
entry = safePageLink(input,input,origin)
require entry
queue = [entry]
while queue and len(report.pages) < maxPages:
    url = shift(queue)
    if visited.has(url): continue
    visited.add(url); resetRedirectRefusalForThisNavigation()
    visitWithReadOnlyPolicy(url)
    if errorOnFirstPage: failJobWithReport()
    if errorOnLaterPage: appendDiagnosticAndContinue()
    appendSafeScreenshotAndPlan()
    enqueueEligibleUnseenLinks()
```
